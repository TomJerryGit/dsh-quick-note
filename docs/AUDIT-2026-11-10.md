## 二、已修复问题

### P0：Agent 工具输出 Schema 与数据不一致

- 现象：`quick_note_search` 调用返回 `tool returned invalid output: "health.intakes" is not a declared property`。
- 原因：用药记录字段 `health.intakes` 已加入 Host/Client 归一化，但工具共享的 `ITEM_SCHEMA.health` 未声明该字段，且 `additionalProperties: false`，运行时校验拒绝整个结果。
- 修复：在 `index.js` 的 `ITEM_SCHEMA.health` 中声明 `intakes`（`date/time/at`）并加入 `required`；所有复用该 Schema 的工具同时生效。
- 回归：新增 Host 检查确认 schema 声明该字段及 required 列表。

### P1：日历/时间轴用药计划重复渲染

- 现象：一个每天 08:00/20:00 的用药计划，在月历每天生成两个 chip，未来 7 天时间轴也每天两行，视觉噪音大且延长页面。
- 修复：按“计划/天”聚合为一个事件，标签显示 `Drug A ×2`，首个时间用于 chip 排序；悬停 tooltip 显示完整时间列表。
- 效果：同一计划每天从 2 个事件降为 1 个；时间轴同理。

### P1：42 天日历事件重复计算

- 现象：月计数、选中日、42 个日期格、未来时间轴分别全量扫描 items；月切换/刷新时计算量叠加。
- 修复：在日历面板内增加按天 `Map` 缓存，事件数组只计算一次；同日多次读取命中缓存。

### P2：日历日期按钮可访问性不足

- 修复：日期按钮 `aria-label` 增加当天事件数（复用 `batchCount` 文案），并增加 `aria-pressed` 表示选中日期。

### P2：补充优化（v1.36.1）

### P1：自动降费能力未启用（v1.39.0）

- 现象：官方 `compaction-basic`、`tool-result-pruner`、`command-compact` 三个自动降费插件均为 inactive；长会话上下文持续增长，缓存输入费用占 58%。
- 修复：
  - 启用 `compaction-basic`（`auto: true`、阈值 0.7、保留 0.35）、`tool-result-pruner`、`command-compact`
  - 新增 Host 只读接口 `/api/quick-note/savings`：读取 compaction/pruner/command、tokenMeter、agents 实时状态与全部 live session 的上下文压力
  - 优化中心新增「自动省钱」面板：能力状态、当前会话上下文占比/压力/预计可压缩量、每日/月度预算、打开插件设置
- 实测：
  - 当前会话 `D:\DSTools`：368,238 / 1,048,576（35.1%），未达压缩阈值
  - 高压力会话 `D:\beeofficeV`：720,972 / 1,048,576（68.8%），预计可压缩 196,684 tokens
  - 压缩能力：✓ 自动压缩、✓ 工具结果裁剪、✓ 压缩命令
- 新会话：首条消息后即可在面板查看压力；达到配置阈值后由 `agent/pre-step` 自动触发，无需手动操作。
