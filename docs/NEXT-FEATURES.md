## 1. 审计摘要

### 1.1 做得好的地方

| 维度 | 现状 |
|---|---|
| 数据完整性 | 乐观锁 `If-Match` + 409 合并、条目级 rev、软删除墓碑（上限 200）、原子写、序列化写入、mirror 兜底、10 份滚动备份 |
| 安全 | 只读路由 loopback token、Origin 校验、写接口不暴露公网；安装包下载/审批哈希确认 |
| 测试 | 111 Host + 109 Client 断言；冲突合并、软删除、备份、用量/价值、版本通道均有回归 |
| 可维护一致性 | 中央 `VIEW_META`/`KIND_META`、`Segmented`、`settings` 统一写入、`protectedRequest` 等共享层 |
| UI | 6 个顶层标签（概览/知识/计划/健康/记录/分析）、子标签持久化、主题令牌 + 密度/强调色、reduced-motion、骨架屏 |
| Agent 集成 | 7 个工具 + 每日简报注入 + 助手消息「存为笔记」动作 |

### 1.2 主要风险与技术债

| # | 风险 | 影响 | 建议 |
|---|---|---|---|
| R1 | Client 单文件 473KB、无构建步骤、组件+IIFE+CSS 全在一个文件 | 维护/审查成本高，易出「截图才发现」的布局/交互 bug | 引入 esbuild 打包 `src/` → `client.js`（保留运行时约束），CSS 分层；P1 |
| R2 | 测试是 React 桩渲染，无真实浏览器/DOM/CSS | 无法捕捉布局、滚动、焦点、真实事件问题 | 加 Playwright/electron 冒烟（打开面板截图 + 关键点击）；P1 |
| R3 | 全量文档轮询（12s）+ 整包 PUT | 条目多时写放大、流量大 | 增量接口 `/state?since=rev`、PUT diff 或 per-item 路由；P1 |
| R4 | 列表无虚拟化；日历每次渲染 `42 × N` 事件计算 | 1 万条目标下首屏/滚动风险 | 虚拟列表（按行高窗口化）+ memo 化事件索引；P1 |
| R5 | 导入 JSON 无大小/字段上限 | 超大文件可能卡死或脏数据 | 限制大小/条数、schema 校验、导入预览；P2 |
| R6 | 数据文件 version=1，无迁移框架 | 未来 schema 变更成本高 | 增加 migration registry（v1→v2…）；P2 |
| R7 | i18n 仅 zh/en；DSH 0.2.2 已增加 ja/es/fr/de/ru/pt-BR | 非中英用户看到英文回退 | 注册更多 locale 字典或先接受英文回退；P1/P2 |
| R8 | 移动/触屏适配仅靠媒体查询，操作按钮依赖 hover | 新版本 DSH 强化手机/平板，插件体验下降 | 触控目标 ≥40px、hover 操作改长按/更多菜单；P1 |
| R9 | 通知只覆盖用药/本地提醒；无 Host 级定时推送 | 关闭面板或长时间不打开时提醒弱 | Host `timer` + 会话/桌面通知桥；P2 |
| R10 | 版本管理可安装任意 https 安装包（哈希确认）但无发布者签名 | 供应链风险 | 文档标注、优先官方源、可选签名白名单；P2 |
| R11 | 无附件/图片/富文本，笔记只能纯文本 | 与用户对「知识管理」的预期有差距 | Host `attachments` 服务 + 图片/文件引用；P0 |
| R12 | 无 Markdown 预览/文件导入导出（仅 JSON/CSV 报表） | Obsidian/本地 Markdown 用户迁移难 | Markdown 文件夹导入/导出；P1 |

### 2.2 可直接复用的 Host 服务（关键）

- `commands`：注册人类斜杠命令 → **聊天内直接建/查条目**（最高性价比）。
- `attachments`：图片/文件不可变存储与引用 → 笔记附件、图片预览。
- `speechToText`：语音转写 → 语音速记。
- `translator` / `cotTranslation`：文本翻译 → 双语笔记/复习卡。
- `web.search` / `web.fetch`：URL 抓取 → 网页剪藏。
- `sessions.search`（Client）+ `sessions`（Host）：会话内容检索 → 会话摘要保存。
- `systemPrompt.context`：每日简报已有，可扩展**未来 7 天计划/用药/复习到期**摘要。
- `timer`：Host 定时器 → 到期提醒/每日汇总。
- `storageDomain` / `fs`：结构化存储/文件读写 → Markdown 导入导出。

## 3. 新需求提案（按性价比排序）

> 价值：用户价值；成本：相对工作量（1=小，5=大）；风险：实现/兼容风险。
> 验收标准均为「至少 1 条 Host/Client 回归 + 实机验证」。

### P0（建议下一版立即做）

#### P0-1 DSH 斜杠命令与聊天内捕获（价值 5 / 成本 2 / 风险 1）
- `/note <文本>`、`/task <标题> [due]`、`/plan`、`/review`、`/search <关键词>`、`/capture`
- 复用现有 store 与工具逻辑；命令结果返回简短 Markdown（条目链接/ID）
- 验收：聊天输入 `/note 买菜` 后侧栏出现条目；`/search` 命中；错误提示友好
- 理由：把管理台从「要打开面板」变成「聊天即录入」，是当前最高杠杆

#### P0-2 图片/附件笔记（价值 5 / 成本 3 / 风险 2）
- 笔记编辑器支持拖拽/粘贴图片、附件；列表/详情缩略图；删除引用不影响其他条目
- 基于 Host `attachments`（图片/文件 ref）或插件自有 `$DSH_HOME/quick-note/files/`
- 导出备份包含引用（或可选内嵌）
- 验收：粘贴图片保存后刷新仍在；Markdown 导出含链接；无 dangling 引用

#### P0-3 会话/工作区上下文捕获增强（价值 4 / 成本 2 / 风险 1）
- 助手动作已有「存为笔记」；新增：
  - 会话行操作「保存会话摘要为笔记/任务」
  - 输入区 dock「捕获选区/最后一轮」→ 笔记（带「对话」标签）
  - 去重（已有 body 相同判断）与来源链接
- 验收：从会话行保存后知识页可见，带来源标签；重复保存提示已存在

## 5. 验收与度量

每个提案合并前必须：

1. Host/Client 回归至少各 1 条（现有基线 111/109 只增不减）；
2. `package.json` 版本 + README/ROADMAP 更新；
3. 字典键 100% 使用率（新增键同时中英）；
4. 主题令牌合规（无字面色）、CSS 括号平衡；
5. 实机验证：面板可打开、核心路径点击可用、数据 revision 正常。

建议跟踪指标：面板首屏时间、10k 条目滚动 FPS、每日活跃条目数、复习完成率、命令使用次数、附件体积、同步失败率。

## 6. 备注：不推荐做的事

- 把健康/记录合并进知识（语义差异大，已在 v1.11.0 否决）
- 让插件自行抓取/安装第三方安装包（供应链风险高，保持官方源 + 哈希确认）
- 在插件内内置 LLM 调用（应由 DSH 的 Agent 层统一治理；通过命令/工具/子代理间接使用）
